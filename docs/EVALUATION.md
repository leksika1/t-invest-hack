# План оценки качества

Эксперимент ещё не проведён. Корпус 30–50 реальных выпусков, результаты и измеренные проценты отсутствуют. Ниже протокол этапа 5 и целевые пороги анкеты, а не достигнутые показатели. `backend/eval/` и команды его запуска пока не реализованы.

## Гипотеза и сравнение

RAG + LLM по схеме с проверкой цитат находит юридические условия из неоднородных документов лучше простого regex/keyword-экстрактора, сохраняя точность стандартных полей и не показывая неподтверждённые значения. Проверка гипотезы — одинаковые документы, снимки ISS и нормализация для baseline и основного конвейера; ручные исправления не участвуют в первичной метрике.

Baseline: без LLM и эмбеддингов, фиксированный набор ключевых слов/регулярных выражений по коду поля, ближайший пункт как цитата, извлечение простых дат/чисел. Проверка цитат и ISS та же. Словари/правила настраиваются только на dev. Отдельно показать ISS-only режим: он нужен для доступности, но не доказывает качество извлечения из PDF и не считается победой над baseline.

Уточнение 1b: основной прогон через OpenRouter, исходная модель google/gemini-2.5-flash (в отчёте фиксировать фактически вызванную). Стоимость usage.cost приоритетна, fallback по конфигу маркируется отдельно. Эмбеддинги опциональны. Для воспроизводимого сравнения фиксируется выбранный пользователем комплект с origins и датами; baseline и LLM получают один набор. Отдельно оценить полноту/точность автосбора ПРАЙМ/СКРИН и долю ассистированной/ручной загрузки; ошибки коллектора не скрывать оценкой только заранее полных PDF. Состояния официального Интерфакса/блокировок и исключённые пользователем документы показывать в отчёте.

## Выборка и разметка

1. Команда собирает 30–50 биржевых корпоративных выпусков, включая ВДО. Охватить разных эмитентов/составителей, fixed/floating/variable, put/call, амортизацию, обеспечение, сканы и несколько редакций. Фактическое распределение опубликовать, не обещать заранее долю сканов.
2. Для каждого выпуска сохранить комплект PDF с sha256, типом и provenance, дату актуальности, снимок описания ISS и полного bondization. Зафиксировать, какие документы отсутствуют. Не сравнивать старый PDF с незаметно обновившимся ISS.
3. Предлагаемое разбиение 30% dev / 70% test, целыми эмитентами (родственные выпуски одного эмитента в одной части). Число выпусков, seed и список ID записать в manifest. Порог fuzzy/confidence, top-k и промпты заморозить перед test; test не использовать для настройки.
4. Разметчик отмечает все 15 полей и атомарные условия внутри массивов, цитаты/страницы/пункты, `not_found`, либо `unscorable` с причиной. Второй проверяющий сверяет каждый выпуск; разногласия разрешаются до запуска и фиксируются. Для стандартных полей ISS — эталон сверки, но документное значение также размечается: корректно обнаруженное реальное расхождение не является ошибкой модели.
5. Нет данных в неполном корпусе → not_found с причиной, не утверждение об отсутствии в выпуске. `unscorable` (битый PDF, неопределимая актуальность и т.п.) учитывается отдельно, знаменатели и исключения публикуются. Нельзя скрывать трудные случаи исключением без отчёта.

Пользовательские confirmed/corrected — кандидаты на пополнение gold после второго проверяющего, исходный результат сохраняется. Синтетические 1–2 примера этапа 5 проверяют формат и работу scorer, но не заменяют реальный корпус.

## Предлагаемый gold JSON

Один JSON на выпуск; полная запись содержит ровно 15 кодов CARD_FIELDS. Пример сокращён до двух полей и синтетический:

```json
{
  "schema_version":"1",
  "isin":"RU000A10AXF7",
  "as_of":"2026-11-15",
  "documents":[{"document_id":"gold-decision","filename":"decision.pdf","sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}],
  "iss_fixture":"iss/RU000A10AXF7.json",
  "fields":{
    "face_value":{
      "value":{"amount":"1000.00","currency":"RUB"},"not_found":false,
      "quote":"Номинальная стоимость каждой облигации составляет 1 000 российских рублей.",
      "document_id":"gold-decision","page":1,"clause":"3.1","evidence":[],
      "iss_value":{"amount":"1000.00","currency":"RUB"},"expected_status":"verified_iss"
    },
    "cross_default":{"value":null,"not_found":true,"quote":null,"document_id":null,"page":null,"clause":null,"evidence":[],"reason":"not_in_documents"}
  },
  "review":{"annotators":["A","B"],"resolved":true}
}
```

Для массивов evidence дополнительно связывается с индексом/путём элемента value в gold; scorer сопоставляет условия по заранее заданным признакам, не по буквальному равенству пересказа. Правила сопоставления (триггер, срок, исключение, цена, субъект) фиксируются до test. Gold document_id сопоставляется с ID карточки по sha256 через manifest, не по случайному UUID/имени файла. `unscorable` и причина — отдельные поля, а не not_found.

## Метрики и пороги

| Метрика | Определение | Цель |
|---|---|---|
| Field-level accuracy полей 1–8 | Верные результаты / все оцениваемые пары выпуск–поле (до 8 × N). Для совпадения нужны корректное документное value, источник и статус сверки. При gold mismatch — корректный флаг и оба значения; корректное gold not_found также учитывается | ≥95% |
| Recall рисковых условий | TP / (TP + FN) по атомарным gold-условиям. TP: смысл/критичные параметры верны и цитата подтверждена; скрытые review и пропуски — FN | Для ковенантов и опционов ≥85% |
| Уверенные галлюцинации без цитаты | Количество показанных как факт машинных значений без подтверждения источником документа | 0 |

Для порога recall отдельно публиковать `covenants`, `issuer_call_option` и put-условия, отражённые в offers/offer_procedure, без двойного подсчёта одного условия. Предлагаемая строгая приёмка: ≥85% по каждой из этих категорий и по их объединению; анкету не интерпретировать как разрешение скрыть слабый call высоким recall ковенантов. Для всех 7 рисковых полей дополнительно micro/macro recall и precision; для категорий без положительных примеров — N/A, не 100%.

`needs_review` не засчитывается правильным вместо конкретного gold-значения: иначе можно пройти пороги, скрыв всё. Отдельно сообщать coverage (доля показанных подтверждённых значений), долю review/not_found, false positives на отрицательных примерах, корректность mismatch, время и стоимость на выпуск, OCR-ошибки и retrieval recall. Прямое ISS-only значение исключается из счётчика PDF-галлюцинаций только при честном `source.kind=moex_iss`; этот режим оценивается отдельно.

Наличие цитаты само по себе не доказывает смысловую корректность. Дополнительно считать ответы с подтверждённой, но не поддерживающей значение цитатой и утратой исключений/отрицаний. Все TP рисковых полей на такой малой выборке проверяет человек; самооценка LLM не судья. Проценты сопровождаются абсолютными TP/FP/FN/total и разбивкой по текстовым PDF/сканам, типам купона и группам выпусков.

## Воспроизводимый запуск на этапе 5

Запланированный CLI, сейчас запускать нельзя:

```bash
cd backend
python -m eval.run --gold eval/gold --cards artifacts/cards.json --output artifacts/evaluation.md
python -m eval.baseline --manifest eval/manifest.json --output artifacts/baseline-cards.json
python -m eval.run --gold eval/gold --cards artifacts/baseline-cards.json --output artifacts/baseline.md
```

`--gold` и `--cards` заданы мастер-заданием; `--output`, CLI baseline и manifest — предлагаемый интерфейс этапа 5. `cards.json`: массив полных ответов GET карточки после обработки, до правок. Экспортёр для эксперимента должен сохранить snapshot/manifest и сопоставление документов; Markdown-экспорт UI не является входом scorer. Для платного прогона ключи задаются окружением и предварительно настраивается бюджет.

Отчёт Markdown: размер/состав корпуса и split, версии кода/промптов/схем, model/endpoint без секретов, цены и UTC-день, embedding/FTS режим, OCR, время, расходы, все метрики/знаменатели, сравнение baseline и список ошибок с источниками. Отдельный прогон FakeLLM проверяет механику, не качество реальной модели. Отсутствие сети в unit-тестах не заменяет реального эксперимента.
