## Собственные проверки этапа 2 — 15.11.2026

Сеть доступна. ISS: description содержит EMITTER_ID; `/iss/emitters/{id}.json` → блок emitter, колонка **INN** (также OGRN/TITLE/SHORT_TITLE). Запасной поиск `/iss/securities.json?q={isin}` даёт emitent_inn. Это подтверждено записанными JSON, догадка про EMITTER_INN в description больше не используется. Сохраняем строковый ИНН и точное совпадение ISIN при fallback.

Проверены графики RU000A1048A9, RU000A107UU5, RU000A10C8F3: coupons (coupondate/startdate/initialfacevalue/value/valueprc), amortizations (amortdate/initialfacevalue/value/valueprc/data_source), offers (offerdate/offerdatestart/offerdateend/price/offertype). У первых двух есть оферты и амортизация. `FACEVALUE` в description — остаточный номинал: у RU000A1048A9 это 250, первоначальный по графикам 1000. Нормализация использует initialfacevalue; если оно неизвестно/неоднозначно, номинал null с предупреждением. SUR/RUR нормализуется в RUB. Отсутствующий явный тип купона не восстанавливается по текущей ставке. «Оферта (состоялось)» не означает автоматически put/call: сохраняем raw_type, type=unknown.

ПРАЙМ robots.txt: 200, запретов нет. СКРИН robots.txt: **404**, а не пустой 200 из исходного задания. Отсутствующий robots (404/410) допускает опрос; 403/5xx/сетевая ошибка закрывает автоскачивание, не обходится. Идентификатор клиента BondCardMVP/0.1 (+https://tinvest.leksika1.ru), минимум 1 секунда между запросами домена. AK&M исключён по ограничению задания; e-disclosure не скрейпится.

## Порядок для ISIN

1. ISS: secid, параметры, полные купоны/оферты/амортизация, эмитент/ИНН при наличии; сохранить сырой JSON и fetched_at.
2. Последовательно ПРАЙМ (`disclosure.1prime.ru`) → СКРИН (`disclosure.skrin.ru`) → официальный e-disclosure при доступе. Опросить все разрешённые источники, а не остановиться на первом PDF: комплект может дополняться изменениями. Ошибка/пустота одного не останавливает остальных.
3. Показать найденные документы с типом, источником, URL, датой публикации (если известна), временем получения и статусом разбора. Пользователь исключает лишние/неактуальные документы и добавляет свои PDF. Система не определяет действующую юридическую редакцию по дате скачивания.
4. Завершённый сбор и готовность включённых документов разрешают извлечение. Snapshot фиксирует выбор, sha256 и происхождения; выключение документа не удаляет файл и не меняет старые карточки.
5. Загрузка пользователем доступна всегда, включая отсутствие ИНН, сбой ISS, 403, пустой поиск или отсутствие официального доступа. Полнота автоматического сбора не гарантирована.

## Контракт DocumentSource (проект этапа 2)

- `discover(issue_identity)` принимает ISIN/secid/ИНН/название и возвращает кандидатов и состояние источника, без LLM.
- Кандидат: source, issuer identity и URL страницы, source document ID если есть, тип, название, published_at nullable, download URL, формат PDF/архив, основание связи с выпуском. Совпадения только названия недостаточно для уверенной привязки.
- `fetch(candidate)` потоково получает файл с ограничениями, сохраняет fetched_at, MIME/размер/sha256, ссылку на страницу/загрузку. После проверки PDF общий ingest одинаков для коллектора и загрузки.
- `PrimeSource`: подтверждённый профиль `/Portal/Default.aspx?emId={inn}`, проверка span ctl00_Main_inn; документы GetDocument встроены в скрытые таблицы категорий HTML. Без ИНН — ASP.NET POST формы `/portal/emitents.aspx` по ОГРН/названию и hidden fields. `SkrinSource`: профиль `/disclosure/{inn}` с проверкой ИНН, раздел выпусков `/6`, файлы `/disclosure_docs/`, пагинация `?page=`; без ИНН поиск `/Firms?q=` по ОГРН/названию. Автосбор берёт только строки с ISIN/регномером либо точным токеном серии, общие проспекты без привязки могут быть пропущены и требуют загрузки вручную.
- `EDisclosureSource`: официальный договорной API, `EDISCLOSURE_API_URL` и `EDISCLOSURE_API_KEY`. Реализована заглушка: без пары — `official_access_required`, текст «Нужен официальный доступ»; с парой env до реализации договорного адаптера — `adapter_not_implemented`. Методы API, схема авторизации и тарифы — проверить по договорной спецификации. Капчу/антибот не обходить.
- `UploadDocumentSource`: собственный PDF с типом; источник upload, published_at только если известна, без выдуманного внешнего URL.

Состояние сбора источника: `queued/running/succeeded/empty/official_access_required/adapter_not_implemented/blocked/failed`. `succeeded` означает успешный опрос, а не полноту документов. Parse status документа отдельно: `queued/processing/ready/failed`. Job с частичными результатами может завершиться succeeded с предупреждениями; глобальный сбой до обработки источников — failed. Повтор не стирает прежние документы/выбор пользователя.

## Ассистированный e-disclosure

По ИНН формируется ссылка на страницу поиска эмитента e-disclosure. Реализована ссылка https://www.e-disclosure.ru/poisk-po-kompaniyam, ИНН передаётся отдельным query для копирования; автоматическое заполнение параметра ИНН не заявляется. Целевой API возвращает `search_url` и `query` с ИНН: если проверен параметр, URL содержит URL-encoded ИНН; иначе ссылка на проверенную страницу поиска плюс ИНН для копирования, `mode=manual_query`. До проверки страницы `search_url=null`, показать домен и запрос, не выдавать рабочую ссылку за подтверждённую. Если ИНН неизвестен, query — название и предупреждение.

Пользователь сам открывает сайт, проходит предусмотренные сайтом действия, скачивает PDF и загружает его. Backend не получает/не воспроизводит cookies капчи и не пытается обойти блокировку. Ассистированный режим независим от наличия договорного API.

## Кэш, вежливый доступ и ограничения

- Собственный User-Agent с реальным контактом команды; контакт уточнить. Перед доступом robots.txt, правила сайта и ограничения лицензии проверить; robots не равен лицензии на переиспользование.
- Источники опрашиваются последовательно; внутри домена ограниченная частота, настраиваемая задержка/таймаут, ограниченные ретраи 429/5xx и Retry-After. При 403/капче — blocked, без смены идентичности/прокси для обхода. Ошибка получения robots (кроме 404/410 — отсутствует) → заблокировать автоскачивание, ручная загрузка остаётся.
- Кэш поиска/robots/URL на диске с временем проверки, TTL по умолчанию 3600 с (COLLECTOR_CACHE_SECONDS). При наличии ETag/Last-Modified использовать условные запросы; sha256 — окончательная дедупликация содержимого. Повторный сбор не означает повторное скачивание неизменившегося PDF.
- Один PDF в выпуске по UNIQUE(issue_id, sha256), несколько document_origins сохраняют все источники. Не переносить автоматически признак enabled между разными выпусками. Новые документы включены по умолчанию; существующий пользовательский выбор при повторе сохраняется.
- PDF либо архив: архив временно распаковывается с защитой от выхода за путь, symlink/вложенных архивов и zip-bomb; лимиты загрузки/распаковки — OPERATIONS. Далее только PDF ≤30 МиБ. MIME/расширения недостаточно: проверить сигнатуру и открытие. Сохранять URL/sha256 архива и entry name.
- Любой URL/redirect должен оставаться в разрешённом списке доменов источника и проверенных CDN; список исследовать на этапе 2. Запретить обращения к loopback/private/link-local/служебным адресам на каждом redirect; пользователь не задаёт произвольный download URL. Секреты официального API не пересылаются на другой origin.
- Неясная связь с выпуском/конфликт редакций → предупреждение и проверка человеком; не индексировать документы другого выпуска как достоверный источник. При отсутствии данных — «не найдено в переданном корпусе», не «условие отсутствует».

## Форматы и качество

Исходный PDF неизменяемый, в volume по sha256; document_origins хранит source, страницу/URL загрузки, published_at nullable, fetched_at, сведения об архиве. Имя файла не используется как путь. Страницы 1-based, сырой Unicode-текст, ocr и ошибки; chunks сохраняют документ/страницу/пункт. FTS russian всегда, nullable embedding с моделью/размерностью; смена модели требует переиндексации. Выбранный файл и каждый дополнительный источник доступны в карточке/экспорте.

ISS сохраняется сырым JSON + нормализованные поля и время снимка. Карточка фиксирует выбранный комплект и настройки; правки человека отдельно от машинных результатов. Подробные типы — CARD_FIELDS/API. Кэш не подменяет юридическую актуальность документа.

На выборке измерить сканы/пустые страницы, качество русских таблиц и OCR чисел/отрицаний, неполное раскрытие, ошибочную привязку эмитента/выпуска и конфликт редакций. Доля сканов/ограниченного раскрытия из анкеты — гипотеза, не измеренный факт. Для коллекторов дополнительно: доля найденных требуемых документов, точность привязки, источники/ошибки/время; не смешивать с качеством извлечения из уже готового корпуса.

Ограничения бесплатного ISS, задержки, лимиты, лицензии источников и передача текстов OpenRouter/модели — проверить перед внешним запуском; числовых гарантий нет. Публичность/robots не доказывают право на массовое скачивание и распространение. Сроки хранения/удаления согласовать. Unit-тесты используют HTML/robots/архивы и ISS JSON fixtures, синтетические PDF, FakeLLM, без реальной сети и секретов.

## Отличия от анкеты

Автосбор сохранён как ядро MVP, но защищённый Интерфакс доступен только официально/ассистированно; рабочие веб-коллекторы проектируются для ПРАЙМ/СКРИН. Выбран React вместо бота, PyMuPDF/Tesseract, Postgres FTS + optional pgvector вместо Qdrant, файловый volume вместо S3, OpenRouter вместо неопределённого провайдера, Markdown без PDF-экспорта. Ежедневный мониторинг из анкеты отложен. Прямые ISS-only значения допустимы с честным источником и extracted; правило PDF-цитаты обязательно для LLM-значения.

## Ограничения реализации этапа 2

ПРАЙМ у ряда эмитентов (например, ЛСР и Брусника на проверенных страницах) публикует только сообщения, поэтому документов выпуска там нет. СКРИН поиска по ИНН может вернуть пустую выдачу даже при наличии прямого профиля; основной путь — подтверждённый профиль по ИНН. При отсутствии ИНН поиск по названию/ОГРН принимается только при однозначном результате. Нет внешних поисковых движков или обхода защиты.

Пагинация СКРИН ограничена 12 страницами, кандидаты каждого источника — 20. Общие проспекты/программы без номера конкретного выпуска не включаются автоматически; RAR/7z/DOC/DOCX не распаковываются и не конвертируются. Архивы ZIP проходят размерные/path/symlink/encryption проверки, PDF — сигнатуру и открытие парсером. Невозможность скачать/распознать документ отражается отдельно от not_found поля. Выбор пользователя обязателен для юридической актуальности. Встроенные таблицы/разметка агентств могут измениться, тогда адаптер нужно обновить по новым fixtures.

На этапе 3 эмбеддинги ingest и запроса идут через LLMGateway с общим бюджетом. Без модели/ключа/тарифа либо при ошибке применяется FTS. Реальная совместимость выбранного /embeddings ещё требует проверки без предположения о поддержке конкретной модели. Платных запросов при проверках не было. Настраиваемые лимиты, объём файлового кэша и время OCR учитывать при эксплуатации; автоматической очистки всех истёкших кэш-файлов пока нет.
