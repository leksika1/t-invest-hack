# Поля карточки: целевой контракт

Документ для этапа 3. Сейчас в `app/cards/schema.py` 16 полей: номинал и валюта раздельны. В MVP ровно 15: сохраняем код `face_value`, помещаем валюту в его объект `value`, отдельный `currency` убираем при обновлении схемы и тестов. Шапка (ISIN, secid, эмитент, ИНН, название, листинг при наличии ISS) в эти 15 не входит.

Примеры ниже синтетические, не цитаты реальных выпусков. Расположение разделов типовое и требует проверки по конкретному документу; номера пунктов не фиксируются заранее. Поисковые подсказки предназначены для FTS/RAG и не доказывают наличие условия. Общие статусы и проверка цитат — [ARCHITECTURE.md](ARCHITECTURE.md), оболочка поля — [API.md](API.md). Изменение 1b не меняет 15 полей: поиск идёт только по включённым пользователем документам (ПРАЙМ/СКРИН/официальный Интерфакс/upload), snapshot сохраняет все origins и даты. ИНН в шапке берётся только из проверенного маппинга ISS, точный ключ пока требует проверки, см. DATA.

## Общие типы и сравнение

Даты — `YYYY-MM-DD`, время API — UTC ISO 8601. Деньги, проценты и коэффициенты — десятичные строки, не float. Валюта — нормализованный код; внешние обозначения валюты из ISS сопоставляются явным справочником после проверки. Неизвестное — `null`, не ноль. Для перечислений неизвестный вариант — `unknown` с исходным текстом и `needs_review`.

`value=null` при ненайденном или неподтверждённом результате. Пустой массив означает явное отсутствие, подтверждённое документом; отсутствие строки в ISS не доказывает отсутствие условия. У каждого составного значения есть основной источник и при необходимости дополнительные `evidence`, достаточные для всех элементов. Без полного покрытия элементов цитатами — `needs_review`.

ISS-маппинг ниже — задача проверки на записанных fixtures этапа 2, а не обещание конкретных ключей во всех ответах. Текущий клиент читает только `description`, `bondization` ещё не реализован. Поля 1–8 сравниваются только по реально доступным сопоставимым данным. Даты и целые количества сравниваются точно; Decimal — после приведения единиц/масштаба источника; округление/допуски должны быть закреплены в тестах, не подбираться для совпадения. Графики сравниваются по событиям, а не одной ближайшей дате. Нет сопоставимого ISS → `extracted` с цитатой; расхождение → `mismatch_iss`; частичные/неоднозначные данные → `needs_review`.

## Группа 1. Сверяемые с ISS (8)

### 1. `face_value` — номинал и валюта

- Определение: номинальная стоимость одной облигации при выпуске и валюта номинала; остаточный номинал после амортизации не подменяет первоначальный.
- Формулировка: «Номинальная стоимость каждой облигации составляет 1 000 российских рублей».
- Где: общие параметры выпуска, номинальная стоимость, валюта обязательств.
- `value`: `{"amount":"1000.00","currency":"RUB"}`.
- ISS: описание выпуска, отдельно проверить семантику первоначального/текущего номинала и валюты; обе части должны совпасть.
- Подсказки: «номинальная стоимость каждой облигации», «валюта номинала», «рублей», «остаточная номинальная стоимость».

### 2. `placement_date` — дата размещения

- Определение: дата начала размещения, не регистрация выпуска и не окончание размещения.
- Формулировка: «Дата начала размещения — 15 марта 2027 года».
- Где: порядок и сроки размещения; изменения/сообщение об установленной дате.
- `value`: `{"date":"2027-03-15"}`. Относительное условие без установленной даты не переводить в календарную дату по догадке.
- ISS: сопоставить с датой начала размещения; проверить назначение соответствующего ключа description на fixtures.
- Подсказки: «дата начала размещения», «начало размещения», «срок размещения», «установление даты».

### 3. `maturity_date` — дата погашения

- Определение: плановая дата окончательного погашения, без смешения с put/call и промежуточной амортизацией.
- Формулировка: «Облигации погашаются 15 марта 2030 года».
- Где: порядок и срок погашения, календарь платежей.
- `value`: `{"date":"2030-03-15"}`.
- ISS: плановая дата погашения из описания; при относительном сроке расчёт разрешён только с однозначной базой и правилом календаря, иначе review.
- Подсказки: «дата погашения», «срок погашения», «окончательное погашение», «день с даты начала».

### 4. `coupon_type` — тип купона

- Определение: `fixed` (фиксированная ставка), `floating` (расчёт по формуле), `variable` (ставка устанавливается для периодов), `unknown`.
- Формулировки: «Ставка всех купонов составляет 18%»; «Ключевая ставка Банка России плюс 3 п.п.»; «Ставка последующих купонов определяется эмитентом».
- Где: порядок определения дохода, ставка купона, решения об установлении ставок.
- `value`: `{"type":"floating","description":"Ключевая ставка плюс 3 п.п."}`.
- ISS: проверять наличие явных признаков типа. Одна текущая ставка не доказывает фиксированность на весь срок; при отсутствии классификации не выдавать verified.
- Подсказки: «фиксированная ставка», «переменный купон», «плавающий купон», «определяется эмитентом», «базовая ставка».

### 5. `coupon_rate` — ставка, сумма или формула купона

- Определение: параметры купонного дохода с областью действия (номера периодов). Формула включает базу, спред, дату наблюдения, ограничения и округление, если они указаны.
- Формулировка: «Для купонов 1–4 ставка равна 18% годовых»; «КС + 3 п.п., но не более 25%».
- Где: формула дохода, таблица купонов, изменение ставок, отсылочные пункты.
- `value`: `{"periods":[{"from":1,"to":4,"rate_percent":"18","amount":null}],"formula":null}`; для floating: `{"periods":[],"formula":{"text":"КС + 3 п.п.","base":"КС","spread_pp":"3","cap_percent":null,"floor_percent":null,"observation_rule":null,"rounding_rule":null}}`.
- ISS: ставки/суммы по соответствующим купонам bondization. Различать проценты годовых и денежную выплату; текущая выплата не подтверждает всю формулу. Частичный охват — review.
- Подсказки: «размер купонного дохода», «процентная ставка», «ключевая ставка», «спред», «округление», «порядок определения».

### 6. `coupon_schedule` — частота и график выплат

- Определение: даты, номера и границы купонных периодов; частота не заменяет полный график.
- Формулировка: «Купонный период составляет 91 день; даты выплат указаны в таблице».
- Где: таблица купонных периодов, порядок выплаты дохода.
- `value`: `{"frequency_per_year":4,"period_days":91,"payments":[{"number":1,"start":"2027-03-15","end":"2027-06-14","payment_date":"2027-06-14"}]}`.
- ISS: все купоны bondization с учётом пагинации и периода доступности. Нельзя выводить 4 выплаты в год только из одного интервала 91 день; если частота не установлена, `null`.
- Подсказки: «купонный период», «даты выплаты», «количество купонов», «продолжительность периода», «график».

### 7. `offers` — даты и типы оферт

- Определение: события приобретения/досрочного выкупа, `put` — право владельца, `call` — право эмитента. Не классифицировать любой выкуп как call.
- Формулировка: «Владельцы вправе потребовать приобретения 15 марта 2028 года».
- Где: приобретение облигаций, оферты, сообщения об установлении условий выкупа.
- `value`: `{"events":[{"date":"2028-03-15","type":"put","price_percent":"100"}]}`.
- ISS: блок оферт bondization; проверить смысл дат, типа и цены. При неизвестном типе — `unknown`, review. Пустой блок не равен отсутствию оферт.
- Подсказки: «оферта», «приобретение по требованию владельцев», «put», «call», «право эмитента», «дата выкупа».

### 8. `amortization` — график амортизации

- Определение: частичное и окончательное погашение номинала, даты и размеры с указанием базы процентов.
- Формулировка: «В дату окончания 8-го купона погашается 25% первоначальной номинальной стоимости».
- Где: погашение номинала, амортизационные выплаты, таблица платежей.
- `value`: `{"events":[{"date":"2029-03-15","amount":"250.00","percent":"25","percent_base":"initial_face_value"}]}`.
- ISS: погашения bondization; сравнить даты, суммы и базу, не складывать суммы разных валют. Bullet-выпуск не определять по отсутствию записей.
- Подсказки: «амортизация», «частичное погашение», «доля номинальной стоимости», «непогашенная часть», «график погашения».

## Группа 2. Текстовые рисковые условия (7)

ISS не является источником для полей 9–15: `iss_value=null`, статус при подтверждённых цитатах — `extracted`. Для каждого элемента сохранять исключения, триггер, сроки и отсылки; отсутствие находки не превращать в `false`.

### 9. `covenants` — ковенанты

- Определение: договорные обязательства/финансовые нормативы и последствия нарушения; общий рекламный текст о надёжности сюда не относится.
- Формулировка: «Отношение чистого долга к EBITDA не должно превышать 3,5 на отчётную дату».
- Где: обязательства эмитента, дополнительные условия, основания требования погашения.
- `value`: `{"items":[{"condition":"Чистый долг / EBITDA ≤ 3,5","test_date_rule":"На отчётную дату","consequence":null,"exceptions":null}]}`.
- Подсказки: «ковенант», «финансовые показатели», «обязуется соблюдать», «чистый долг», «EBITDA», «нарушение обязательств».

### 10. `holder_early_redemption` — погашение по требованию владельцев

- Определение: основания и сроки требования владельца при наступлении условий; отделять от обычного put по календарю.
- Формулировка: «При нарушении обязательства владельцы вправе потребовать досрочного погашения в течение 30 дней».
- Где: досрочное погашение по требованию, существенные нарушения, права владельцев.
- `value`: `{"grounds":[{"trigger":"Нарушение обязательства","deadline":"В течение 30 дней","exceptions":null}]}`.
- Подсказки: «досрочное погашение по требованию», «существенное нарушение», «право требовать», «срок предъявления».

### 11. `issuer_call_option` — call-опцион эмитента

- Определение: право эмитента инициировать досрочное погашение/выкуп, условия, цена и уведомление. Поле 7 хранит календарное событие, здесь — правовое условие.
- Формулировка: «Эмитент вправе погасить выпуск досрочно по цене 100% номинала, уведомив за 10 рабочих дней».
- Где: досрочное погашение по усмотрению эмитента, право приобретения.
- `value`: `{"conditions":[{"trigger":"По усмотрению эмитента","date_rule":null,"price_rule":"100% номинала","notice_rule":"За 10 рабочих дней"}]}`.
- Подсказки: «по усмотрению эмитента», «эмитент вправе», «call-опцион», «уведомление о досрочном погашении».

### 12. `guarantee_security` — обеспечение

- Определение: поручительство, оферта третьего лица, залог и пределы обязательств. Эти механизмы не считать юридически тождественными.
- Формулировка: «Исполнение обеспечено поручительством ООО „Пример“ в пределах указанной суммы».
- Где: обеспечение исполнения, сведения о поручителе/залоге, отдельная оферта третьего лица.
- `value`: `{"items":[{"type":"surety","party":"ООО Пример","scope":"В пределах указанной суммы","expiry":null,"exceptions":null}]}`; типы `surety/third_party_offer/pledge/other`.
- Подсказки: «обеспечение», «поручитель», «предмет залога», «оферта третьего лица», «объём ответственности», «без обеспечения».

### 13. `cross_default` — кросс-дефолт

- Определение: последствия неисполнения иных обязательств эмитента/группы для этого выпуска; не обычная просрочка купона самого выпуска.
- Формулировка: «Неисполнение иных долговых обязательств на сумму свыше 100 млн рублей является основанием…».
- Где: существенные нарушения, досрочное погашение, дополнительные условия.
- `value`: `{"items":[{"trigger":"Неисполнение иных долговых обязательств","threshold":{"amount":"100000000","currency":"RUB"},"entities":"Эмитент","grace_period":null,"consequence":null,"exceptions":null}]}`.
- Подсказки: «кросс-дефолт», «иные долговые обязательства», «неисполнение по другим», «пороговая сумма», «льготный период».

### 14. `issuer_restrictions` — ограничения для эмитента

- Определение: ограничения на дивиденды, отчуждение активов, новые долги, залог и реорганизацию; допустимо пересечение с ковенантами с общей ссылкой на пункт.
- Формулировка: «Выплата дивидендов не допускается при превышении установленного долгового показателя».
- Где: обязательства и ограничения эмитента, дополнительные условия.
- `value`: `{"items":[{"action":"Выплата дивидендов","restriction":"Не допускается при превышении показателя","exceptions":null,"consequence":null}]}`.
- Подсказки: «ограничения», «дивиденды», «отчуждение активов», «крупные сделки», «запрет залога», «реорганизация».

### 15. `offer_procedure` — порядок участия в оферте

- Определение: окно требований, способ подачи, посредники, расчёты и привязка к событию из поля 7.
- Формулировка: «Требования направляются через депозитарий в течение последних пяти рабочих дней купонного периода».
- Где: порядок приобретения/подачи требований, текст оферты, уведомления о выкупе.
- `value`: `{"procedures":[{"offer_date":"2028-03-15","window_start":null,"window_end":null,"window_rule":"Последние пять рабочих дней купонного периода","via":"Депозитарий","submission":"Направление требования","settlement_rule":null}]}`.
- Подсказки: «порядок предъявления», «период предъявления», «адресат требования», «через депозитарий», «акцепт оферты», «срок подачи».

Относительные рабочие дни не переводить в точные даты без проверенного календаря и правил. Противоречащие друг другу документы/версии → `needs_review` с обоими источниками; дата загрузки не доказывает юридическую актуальность документа.
